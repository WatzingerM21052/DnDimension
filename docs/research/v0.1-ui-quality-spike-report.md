# v0.1 UI Quality Spike Report (P-04)

**Status:** Akzeptanzkriterien in Chromium nachgewiesen; Edge-Wiederholung offen<br>
**Datum:** 2026-09-27<br>
**Issue:** [#69 UI- und Quality-Toolchain gegen Budgets validieren](https://github.com/WatzingerM21052/DnDimension/issues/69)<br>
**Entscheidung:** [DEC-010](../decisions/DEC-010-custom-design-system-and-lean-quality-toolchain.md) wird bestätigt

## Ergebnis

PR #73 hatte Token → Primitive → Component → Pattern, selbst gehostete Schriften, den Ausschluss des UI-Labs aus dem Production-Build und die Bundle-Budgets belegt. Offen waren Kontrast und Touchziele im echten Browser. `apps/web/e2e/ui-quality.spec.ts` rendert das UI-Lab jetzt in Chromium in beiden Themes und schließt diese Lücke.

## Nachweis

| Kriterium | Nachweis | Status |
|---|---|---|
| Kontrast (WCAG 2.2 AA) | axe mit aktivierter `color-contrast`-Regel auf dem UI-Lab und im geöffneten Dialog, in `night-chart` und `vellum-study` | bestanden nach Farbkorrektur |
| Touchziele | jedes per Zeiger erreichbare, aktive Control misst mindestens `--target-min` (44 px); zusätzlich axe `target-size` | bestanden |
| Tastatur und Fokus | Dialog öffnet per Enter, Fokus liegt im Dialog (React Aria fokussiert den Dialog selbst, damit der Titel angesagt wird), Escape schließt, Fokus kehrt zum Auslöser zurück | bestanden |
| `prefers-reduced-motion` | ohne Präferenz gibt es animierte Elemente, mit `reduce` keine einzige Animation oder Transition über 10 ms | bestanden |
| UI-Lab nicht im Production-Umfang | `check-production-ui` (PR #73) und Smoke-E2E „development labs are not reachable“ (PR #76) | bestanden |
| keine zusätzlichen Werkzeuge | Playwright und axe-core waren bereits Dev-Dependencies; kein Storybook, Cypress oder Material UI | bestanden |

## Befund: Akzentfarbe im hellen Theme

`vellum-study` nutzte `--color-accent-action: #0b7067`. Als Textfarbe des `quiet`-Buttons auf dem Canvas `#e6d8be` ergibt das 4,23:1, unter der AA-Grenze von 4,5:1. jsdom kann Renderfarben nicht prüfen, und der Theme-Vertragstest prüfte dieses Paar nicht. Korrektur: `#09655d` mit 4,93:1 auf Canvas, 6,05:1 auf Workspace und 6,93:1 für weiße Schrift auf der Farbe. Der Vertragstest prüft die Akzentfarbe jetzt auch als Text auf Canvas und Workspace.

## Grenzen der Messung

- Die Größenprüfung zählt nur Controls, die ein Zeiger an ihrer Mitte trifft. Screenreader-only-Controls wie React Arias versteckter „Dismiss“-Button werden so bewusst ausgenommen. Damit die Prüfung nicht leer besteht, verlangt der Test eine Mindestanzahl gemessener Controls.
- Gemessen wird bei 16 px Grundschrift; Zoom und Textvergrößerung sind nicht automatisiert.

## Noch offen

- Stichprobe in Edge unter Windows sowie mit 200 % Zoom.
