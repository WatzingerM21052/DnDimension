# v0.1 PWA Spike Report (P-03)

**Status:** automatisiert in Chromium nachgewiesen; Nachweis in installierter Edge-PWA offen<br>
**Datum:** 2026-09-27<br>
**Issue:** [#71 PWA Offline- und Update-Verhalten validieren](https://github.com/WatzingerM21052/DnDimension/issues/71)

## Ergebnis

`vite-plugin-pwa` 1.3.0 mit Workbox 7.4.1 (`generateSW`) erfüllt den [PWA-, Offline- und Updatevertrag](../spec-planning/pre-code-engineering-blueprint.md#10-pwa--offline--und-updatevertrag). Website und PWA werden aus demselben statischen Build ausgeliefert. Nach dem ersten Besuch startet die App offline. Ein neuer Build wird angeboten, aber nie ohne ausdrückliche Bestätigung aktiviert. Ein eigener Service Worker ist nicht nötig.

## Umsetzung

| Baustein | Entscheidung |
|---|---|
| Registrierung | `registerType: "prompt"`, `injectRegister: false`; die Registrierung wird nur im Production-Build per `lazy()` nachgeladen und blockiert das erste Rendern nicht |
| Precache | nur `html`, `js`, `css`, `woff2`, Manifest und Icons; keine Source Maps; keine `runtimeCaching`-Routen |
| Navigation | App-Shell-Fallback auf `index.html`, ausgenommen `/dev/*` |
| Update | `UpdatePrompt` zeigt „Neue Version verfügbar“. Aktivierung (`SKIP_WAITING` + Reload) erst nach Klick. Stündliche Prüfung nur, wenn online |
| Ungespeicherte Arbeit | Editoren melden offene Entwürfe über `useUnsavedWork`. Solange einer offen ist, bleibt das Update gesperrt, und `beforeunload` warnt |
| DB-Versionskonflikt | `@dndimension/persistence` prüft vor dem Öffnen die installierte IndexedDB-Version. Ein älterer, gecachter Build verweigert mit `NewerSchemaError` jeden Zugriff, statt dass Dexie 4 entfernte Tabellen neu anlegt. `recoverFromNewerSchema()` lädt den neueren Build. Daten werden nie gelöscht |
| Buildidentität | Version und Commit werden zur Buildzeit injiziert und unter `/health` angezeigt; damit ist nachweisbar, welches Artefakt läuft |

## Nachweis der Akzeptanzkriterien

| Kriterium | Nachweis | Status |
|---|---|---|
| Website und PWA verwenden dasselbe Artefakt | E2E „starts offline from the same build“: identische Buildidentität online und offline aus dem Service-Worker-Cache | bestanden (Chromium) |
| Offline-Start nach initialem Laden | E2E: `/` und `/health` laden bei `context.setOffline(true)` | bestanden (Chromium) |
| keine Nutzerdaten im statischen Cache | E2E „caches only the static build“: jeder Cache-Eintrag ist eine Datei aus `dist`; `check:pwa` verbietet Runtime-Routen und Source Maps | bestanden |
| Update wird angeboten, aktiviert sich nicht unkontrolliert | E2E mit zweitem Build: Banner erscheint, normaler Reload behält die alte Version, erst der Klick aktiviert die neue; Unit-Tests sperren das Update bei ungespeicherter Arbeit | bestanden |
| Cache-/DB-Versionskonflikt hat einen getesteten Recovery-Weg | `version-conflict.test.ts` (älterer Build gegen neueres Schema: Zugriff verweigert, Daten und Schema unverändert) und Controller-Tests für `recoverFromNewerSchema` | bestanden (fake-indexeddb) |
| Manifest, Icons, Service Worker bestehen einen automatisierten Mindestcheck | `pnpm check:pwa` im Build: Manifestfelder, PNG-Größen, maskierbares Icon, vollständiger Precache, kein automatisches `skipWaiting` | bestanden |
| Build- und Cachegröße im Budget | Precache 394,5 KiB bei 5 MiB Budget; JS gzip 93,6 KiB bei 180 KiB; Production Build 0,80 MiB bei 50 MiB | bestanden |

Die Befehle `pnpm verify` (inklusive `pnpm test:e2e`) laufen lokal unter Node 24.20.0 durch. Die CI führt sie jetzt auf `ubuntu-latest` und `windows-latest` aus.

## Kosten

- Abhängigkeiten: `vite-plugin-pwa`, `workbox-build` (Dev) und `workbox-window` (Runtime) erhöhen die projektlokalen Dependencies von 205 auf 239 MiB. `workbox-build` bringt Babel/Rollup für die Buildzeit mit.
- Bundle: Haupt-Bundle unverändert (74 KiB gzip). Das Update-UI mit React Aria lädt als eigener Chunk (14 KiB gzip) erst nach dem ersten Rendern; Service Worker und Workbox-Laufzeit zusätzlich 16 KiB.
- Typprüfung: Die Workbox-Typen bestehen `skipLibCheck: false` nicht. `vite.config.ts` wird deshalb in `apps/web/tsconfig.node.json` mit `skipLibCheck` geprüft; App-Code und Tests bleiben voll geprüft. `virtual:pwa-register` ist lokal typisiert.

## Nebenbefund

`.gitattributes` markierte mit `code/** text eol=lf` auch Binärdateien als Text. Jede PNG-Signatur enthält `\r\n` und wäre beim Commit beschädigt worden. Die vorhandenen `woff2`-Schriften waren zufällig nicht betroffen. Bilder und Schriften sind jetzt als `binary` markiert.

## Noch offen vor Abschluss von #71

- Manueller Nachweis in einer installierten Edge-PWA unter Windows: Installation, Offline-Start aus dem Startmenü, Update-Banner.
- Echter Mehrtab-Fall: Upgrade in Tab A, alter Build in Tab B (`onVersionChange` ist implementiert, aber nur mit fake-indexeddb getestet).
- Noch hält kein Produktions-Editor ungespeicherte Arbeit. Die Sperre ist per Unit-Test belegt und muss mit dem ersten echten Editor (v0.4) per E2E nachgewiesen werden.
- Das statische Hosting muss unbekannte Pfade auf `index.html` umschreiben. Der E2E-Server tut das, ein konkreter Hosting-Anbieter ist noch nicht gewählt.
