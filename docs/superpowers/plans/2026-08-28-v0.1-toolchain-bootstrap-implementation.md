# v0.1 Toolchain Bootstrap Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Einen reproduzierbaren, speichereffizienten pnpm-Workspace mit minimaler React-App, strengem TypeScript-Kern, Quality Gates, sicheren Bereinigungsbefehlen und messbarem Größenreport liefern und damit GitHub-Spike #70 abschließen.

**Architecture:** Der Bootstrap beweist nur den kleinsten vertikalen technischen Pfad aus Browser-App und frameworkfreiem Core-Package. Fachliche Produktfunktionen, Dexie, PWA, React Aria, Motion und SRD-Import bleiben in ihren eigenen Validierungsplänen, damit eine negative Spike-Erkenntnis keinen Produktcode zurückbauen muss.

**Tech Stack:** Node.js 24 LTS (lokal mindestens 24.11.0; CI-Referenz 24.20.0), Corepack, pnpm 11.19.0 Workspace, TypeScript strict, React, Vite, Vitest, React Testing Library, ESLint, Prettier und GitHub Actions.

**Spec:** [Pre-Code Engineering Blueprint](../../spec-planning/pre-code-engineering-blueprint.md), insbesondere Abschnitte 4, 5, 14 bis 16 und 18 bis 21.

## Global Constraints

- Der ausführbare Workspace liegt vollständig unter `<repository>/code`. Sofern nicht ausdrücklich `docs/`, `.github/` oder die Repositorywurzel genannt sind, sind alle Datei- und Befehlsangaben dieses Plans relativ zu `code/` zu verstehen.
- Git-Kommandos laufen aus der Repositorywurzel; pnpm-, TypeScript-, Vite-, Vitest- und Tooling-Kommandos aus `code/`.

- TypeScript läuft mit strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes und useUnknownInCatchVariables.
- Domain-, Rules- und Application-Code bleibt unabhängig von React, Dexie, Cloud- und KI-Anbietern.
- Private Referenzdateien unter private-library und lokale Arbeit unter tmp werden weder gelesen, kopiert, gecacht noch in Build- oder Testartefakte aufgenommen.
- Der Bootstrap installiert weder Docker, Electron, Android SDK, Tauri/Rust, Storybook, Cypress noch lokale Playwright-Browserpakete.
- Die Production-Ausgabe ohne optionale Medien bleibt höchstens 50 MB groß.
- Projektlokale Dependencies zielen auf weniger als 1 GB; der gemeinsame pnpm-Store warnt ab 2 GB.
- Vite-/Transform-Caches warnen ab 300 MB; Testreports, Screenshots, Videos und Coverage bleiben zusammen höchstens 250 MB.
- clean, clean:test, clean:cache und clean:deep dürfen ausschließlich explizit erlaubte reproduzierbare Pfade innerhalb des Repositorys entfernen.
- v1 benötigt keinen bezahlten Dienst und der Bootstrap keine Cloudressource.
- Jede Dependency wird exakt im Lockfile und als genaue package.json-Version gespeichert.
- Lokal wird kein zusätzlicher Browser heruntergeladen; spätere E2E-Schritte verwenden vorhandenen Edge.
- Dieses Dokument implementiert #70. #20, #21, #69 und #71 bleiben eigene, nachgelagerte Validierungspläne.

- [ ] **Step 6: Build-Info ohne Runtime-Framework implementieren**

Create packages/core/src/build-info.ts:

~~~ts
import { err, ok, type Result } from "./result";

export type BuildInfo = Readonly<{
  version: string;
  commit: string;
}>;

export type BuildInfoError = Readonly<{
  code: "invalid_build_info";
  fields: readonly string[];
}>;

export const parseBuildInfo = (
  raw: unknown,
): Result<BuildInfo, BuildInfoError> => {
  if (typeof raw !== "object" || raw === null) {
    return err({ code: "invalid_build_info", fields: ["root"] });
  }

  const input = raw as Record<string, unknown>;
  const fields = [
    typeof input.version === "string" && input.version.trim().length > 0
      ? null
      : "version",
    typeof input.commit === "string" && input.commit.trim().length > 0
      ? null
      : "commit",
  ].filter((field): field is string => field !== null);

  return fields.length > 0
    ? err({ code: "invalid_build_info", fields })
    : ok({ version: input.version as string, commit: input.commit as string });
};
~~~

Create tooling/scripts/check-import-boundaries.mjs. Der öffentliche Vertrag lautet:

~~~js
/**
 * @typedef {{
 *   code: "package_deep_import" | "cross_unit_relative_import";
 *   file: string;
 *   specifier: string;
 * }} ImportViolation
 */

export const analyzeFiles = ({ root, sources }) => ({

  /** @type {string[][]} */ cycles: [],
~~~

Die Implementierung verwendet die bereits installierte TypeScript-API preProcessFile für importedFiles und referencedFiles. Sie bestimmt die Workspace-Einheit ausschließlich aus apps/<name> oder packages/<name>, lehnt @dndimension/<name>/src/... ab und lehnt jeden relativen Import ab, dessen aufgelöster Zielpfad in einer anderen Workspace-Einheit liegt. Öffentliche @dndimension/<name>-Imports bilden einen gerichteten Graphen.

Die Zyklussuche traversiert Package-Namen lexikografisch und meldet jeden Zyklus ab seinem lexikografisch kleinsten Knoten genau einmal. Der CLI-Pfad sammelt rekursiv .ts/.tsx-Dateien unter apps und packages, ignoriert dist und node_modules, gibt jeden Verstoß mit Code, Datei und Specifier aus und beendet sich bei einem Verstoß oder Zyklus mit Exitcode 1, sonst mit Exitcode 0.

Der ausführbare Abschlussblock lautet:

~~~js
const result = analyzeFiles({ root: process.cwd(), sources: collectSources() });
for (const violation of result.violations) {
  console.error(
    violation.code + ": " + violation.file + " -> " + violation.specifier,
  );
}
for (const cycle of result.cycles) {
  console.error("package_cycle: " + cycle.join(" -> "));
}
process.exitCode =
  result.violations.length > 0 || result.cycles.length > 0 ? 1 : 0;
~~~
